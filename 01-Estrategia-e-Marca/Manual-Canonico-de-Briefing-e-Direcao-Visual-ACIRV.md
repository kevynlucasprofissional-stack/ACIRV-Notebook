# Manual Canônico de Briefing e Direção Visual da ACIRV

> [!summary] Fonte canônica para briefings visuais
> Este documento é o **ponto único de entrada para criação de briefings visuais da ACIRV**. Ele unifica a estrutura editorial e operacional antes mantida no `PADRAO_BRIEFING_PRODUCAO.md` do Hermes com as regras necessárias de identidade, direção visual e legibilidade do [[Design-System-ACIRV]]. Um briefing pode ser criado corretamente usando apenas este arquivo.

## 0. Papel e autoridade

Este manual existe para responder a duas perguntas ao mesmo tempo:

1. **Como um briefing da ACIRV deve ser formatado?**
2. **Que direção visual esse briefing deve orientar?**

Arquitetura de autoridade:

1. `000-Arquivos-originais/DESIGN SYSTEM.md` — fonte primária imutável;
2. [[Design-System-ACIRV]] — autoridade ampla de identidade visual e sistema de design;
3. **este manual** — autoridade canônica para criação de briefings visuais e peças de comunicação;
4. `Hermes/.../04-moodboard/MOODBOARD.md` — projeção operacional `ACIRV-MOOD-v1`;
5. arquivos do planejamento e briefings de campanhas — aplicação específica.

### Regra prática

Para **criar um briefing**, este documento deve bastar.

Consultar o Design System completo somente quando:
- surgir uma exceção não coberta aqui;
- a entrega não for uma peça de comunicação/social media;
- for necessário decidir uma nova regra permanente de marca.

O briefing nunca deve criar silenciosamente uma regra visual que contradiga o Design System.

# PARTE I — O QUE É UM BRIEFING PRONTO

## 1. Princípio

O planejamento editorial define **o que comunicar e por quê**.

O briefing de produção transforma isso em uma instrução executável que define:
- o que exatamente entra na arte;
- em qual formato;
- em quantos slides;
- qual informação domina;
- qual linguagem visual usar;
- quais assets são necessários;
- o que não pode ser inventado;
- quais dados ainda precisam de validação.

> **A pessoa que recebe o briefing não deve precisar escrever a copy, pesquisar um fato institucional ou adivinhar a intenção da peça.**

## 2. Critério de PRODUÇÃO_PRONTA

Uma pauta só pode ser tratada como pronta quando possuir:

1. objetivo editorial curto e claro;
2. formato e dimensões;
3. número exato de slides;
4. texto exato de cada slide;
5. hierarquia textual quando útil;
6. direção visual de cada slide;
7. assets e referências necessários;
8. restrições / `NÃO FAZER`;
9. legenda final, quando aplicável;
10. dados pendentes claramente marcados;
11. CTA exato;
12. uma pessoa terceira consegue produzir sem inventar conteúdo.

Se a designer ainda precisa decidir **o que escrever**, a pauta não está pronta.

## 3. Estados recomendados

- `PAUTA_EDITORIAL` — ideia ainda não expandida;
- `BLOCKED_EDITORIAL_BRIEFING` — falta desenvolvimento editorial;
- `BLOCKED_DATA_VALIDATION` — a mensagem depende de dado não confirmado;
- `PRODUÇÃO_PRONTA_COM_ASSET_PENDENTE` — texto/direção fechados, mas falta foto/logo/QR/arquivo;
- `PRODUÇÃO_PRONTA` — pronta para execução;
- `TRELLO_SYNC_PENDENTE` — pronta no GitHub, ainda não sincronizada;
- `TRELLO_SYNC_OK` — briefing sincronizado;
- `REVISAO_PENDENTE` — peça produzida aguardando revisão.

# PARTE II — SISTEMA VISUAL QUE TODO BRIEFING DEVE CONHECER

## 4. Conceito central da marca

Tema: **Conectar para Crescer**.

Conceito visual: **Tradição em Movimento**.

A ACIRV deve parecer:
- institucional sem burocracia;
- moderna sem parecer startup genérica;
- vibrante sem parecer infantil;
- humana sem perder autoridade;
- empresarial sem rigidez;
- local sem perder ambição;
- organizada, mas viva;
- variada, mas reconhecível.

Arquétipos:
- **Sábio** — clareza, autoridade e credibilidade;
- **Conector** — proximidade, rede, articulação e movimento.

Toda peça deve reforçar pelo menos um objetivo:
- pertencimento;
- resultados;
- autoridade;
- proximidade;
- captação.

## 5. Princípios de direção visual

1. **Clareza antes de ornamento.**
2. **Hierarquia antes de densidade.**
3. **Legibilidade antes de “caber tudo”.**
4. **Pessoas e histórias reais antes de banco genérico.**
5. **Azul como âncora; cores vibrantes com função.**
6. **Variedade controlada, não repetição de template.**
7. **A estética deve servir à mensagem.**
8. **A arte precisa funcionar no celular sem zoom.**
9. **Reduzir copy antes de reduzir fonte.**
10. **Uma peça pode variar muito sem deixar de parecer ACIRV.**

# PARTE III — CORES E BACKGROUNDS

## 6. Tokens cromáticos

| Papel | Cor |
|---|---:|
| Azul institucional | `#0E1EB2` |
| Azul-claro / comunicação | `#039DE3` |
| Laranja / conexão | `#FF7C31` |
| Verde / crescimento | `#27E300` |
| Amarelo / destaque | `#EAFF00` |
| Branco | `#FFFFFF` |
| Branco suave | `#F6F8FC` |
| Texto primário | `#101828` |
| Texto secundário | `#475467` |
| Borda | `#D0D5DD` |

Aproximações do moodboard podem orientar aparência, mas não substituem os tokens:
- azul elétrico ~`#003DC5`;
- azul profundo ~`#000EB4`;
- azul-marinho ~`#080890`;
- verde neon ~`#2DDE24`;
- laranja percebido ~`#DE733A`;
- ciano ~`#027AB0` a `#129CDF`.

### Papéis semânticos

- azul = estrutura, autoridade e identidade;
- ciano = comunicação, informação e digital;
- laranja = ação, conexão, evento e temporalidade;
- verde = crescimento, progresso e benefício;
- amarelo = conquista e atenção pontual;
- roxo = transição/gradiente auxiliar, não cor estrutural.

**O azul é a âncora.**

Evitar dar a todas as cores a mesma intensidade.

## 7. Famílias oficiais de background

### A. Cor sólida
Uso:
- mensagem curta;
- peça gráfica;
- campanha de reconhecimento rápido;
- outdoor;
- capa de alto impacto.

### B. Degradê monocromático
Uso:
- profundidade;
- institucionalidade;
- variação sem introduzir nova cor.

### C. Degradê fluido clássico
Principalmente azul + verde.

Comunica:
- conexão;
- movimento;
- crescimento;
- energia digital.

### D. Degradê experimental
Azul + laranja, ciano, verde, amarelo ou roxo auxiliar.

Regras:
- preservar um eixo dominante;
- não virar arco-íris;
- manter superfície de leitura;
- usar a cor secundária com função;
- variar composição e direção.

**Azul + laranja** é combinação validada para contraste forte em campanhas e peças de transição.

### E. Fotografia tratada
Usar quando a história humana ou documental for mais importante que a abstração gráfica.

Tratamentos permitidos:
- overlay azul;
- duotone;
- recorte;
- colagem;
- gradiente sobre imagem;
- foto cheia com área negativa;
- bloco cromático de proteção de texto.

# PARTE IV — TIPOGRAFIA E LEGIBILIDADE

## 8. Tipografia

Fonte principal: **Campuni**.

Fallback:
1. Montserrat;
2. Arial;
3. sans-serif.

Regras:
- títulos grandes;
- contraste claro entre pesos e tamanhos;
- caixa alta seletiva;
- palavras-chave destacadas;
- preferir alinhamento à esquerda;
- centralização apenas quando a composição pedir;
- evitar parágrafos longos na arte;
- evitar muitas famílias e muitos níveis de hierarquia;
- CTA, data, local e assinatura não podem virar microtexto.

### Regra crítica

> **Contraste bom não compensa fonte pequena.**

Se uma informação importante exige zoom:
- reduzir copy;
- aumentar fonte;
- simplificar composição;
- criar outro slide.

## 9. Contraste

Referência mínima:
- 4.5:1 para texto normal;
- 3:1 para texto grande e elementos essenciais.

Preferir:
- branco sobre azul institucional;
- texto escuro sobre verde, amarelo, laranja e azul-claro quando necessário.

Evitar:
- branco pequeno sobre amarelo, verde, laranja ou azul-claro;
- depender de glow/sombra para “salvar” contraste ruim;
- comunicar informação apenas por cor.

---

# PARTE V — FOTOGRAFIA, PESSOAS E IMAGENS GERADAS

## 10. Prioridade de imagens

1. pessoas reais da ACIRV;
2. associados e empresários;
3. equipe e parceiros;
4. eventos e encontros reais;
5. comércio/trabalho local;
6. objetos e produtos em pauta técnica;
7. imagem gerada quando ela for conceito, cenário ou suporte e não substituir indevidamente uma pessoa real.

## 11. Pessoa identificável

Quando o briefing for sobre alguém real:
- usar foto real/autorizada;
- informar o asset;
- não pedir à IA para gerar uma pessoa “parecida”;
- não alterar identidade, rosto ou aparência de forma fantasiosa.

## 12. Texto sobre foto

Se o fundo for detalhado, usar pelo menos uma proteção:
- caixa;
- faixa;
- overlay;
- gradiente localizado;
- desfoque;
- área negativa;
- recorte.

Nunca aceitar texto pequeno diretamente sobre uma área visualmente complexa.

---

# PARTE VI — LINGUAGEM GRÁFICA

## 13. Elementos disponíveis

Podem aparecer:
- linhas e ondas;
- redes e nós;
- cruzamentos;
- blocos marca-texto;
- faixas;
- recortes;
- colagem;
- contornos;
- texturas discretas;
- ícones simples;
- setas;
- formas ascendentes;
- gradientes.

Só usar quando servirem para:
- organizar;
- conectar;
- enfatizar;
- explicar.

Não decorar gratuitamente.

## 14. Efeitos

Preferir:
- sobreposição controlada;
- sombra suave;
- contraste de superfícies;
- profundidade por cor;
- overlays.

Evitar:
- glassmorphism pesado;
- neon excessivo;
- 3D gratuito;
- reflexo metálico;
- sombra pesada;
- estética futurista genérica.

---

# PARTE VII — COMPOSIÇÃO POR FORMATO

## 15. Post de 1 slide

Deve ter:
- 1 gancho dominante;
- 1 ideia/imagem central;
- 1 CTA ou assinatura secundária;
- respiro suficiente.

## 16. Post de 2 slides

### Slide 1 — capa
- gancho curto;
- força de peça única;
- alto contraste;
- não entregar toda a legenda.

### Slide 2 — fechamento
- CTA claro;
- composição mais simples;
- bastante respiro;
- não adicionar um “terceiro conteúdo” só para preencher.

## 17. Carrossel

- capa forte;
- narrativa progressiva;
- alternância entre texto, foto, listas curtas e respiro;
- continuidade de margens, cores e assinatura;
- último slide com ação inequívoca.

## 18. Capa

Toda capa estratégica deve definir:
- gancho;
- palavra/frase de maior destaque;
- tipo de imagem ou conceito;
- densidade;
- família de background;
- cor de acento;
- relação com ACIRV-MOOD-v1.

# PARTE VIII — REFERÊNCIAS DO MOODBOARD

## 19. Regra de peso

> **Quanto maior a peça no moodboard composto, maior o peso dela como referência.**

- `PESO 4 — ÂNCORA`: hierarquia, ritmo, contraste e sensação geral;
- `PESO 2 — FORTE`: amplia repertório;
- `PESO 1 — COMPLEMENTAR`: fornece solução pontual.

Não fazer média simples entre todas.

## 20. Âncoras principais

### “A força da ACIRV tem nome: O SEU!”
Usar como referência para:
- fotografia real;
- overlay azul;
- título muito grande;
- branco + verde;
- laranja pontual;
- respiro;
- linguagem humana.

### “08 Mar — Dia Internacional da Mulher”
Usar como referência para:
- colagem editorial;
- pessoas reais;
- azul dominante;
- acentos controlados;
- contemporaneidade.

### “Conectar para Crescer”
Usar como referência para:
- gradientes;
- rede/movimento;
- palavras-chave em verde/amarelo;
- mensagens curtas.

### Comércio local / Dia do Comerciante
Usar como referência para:
- fotografia documental;
- overlay azul;
- cotidiano empresarial;
- blocos/marca-texto;
- significado acima de decoração.

## 21. Referências fortes

### Associativismo
- foto coletiva;
- azul;
- título branco + palavra verde;
- linhas/conexões;
- rede e ação coletiva.

### Serviços e benefícios
- azul-marinho;
- recortes;
- contornos;
- branco/amarelo/verde;
- CTA compacto.

### SudoExpo
Cores saturadas podem ser usadas como variação de campanha, não como padrão universal.

# PARTE IX — ESTRUTURA CANÔNICA DO BRIEFING

## 22. Template obrigatório

```text

[quando houver]

PUBLICAÇÃO: DD/MM/AAAA

[Uma frase curta dizendo o que a peça deve fazer.]

...

DIREÇÃO VISUAL GERAL:
[Conceito visual da peça/campanha, família de background, ritmo, sensação.]

DIREÇÃO VISUAL POR SLIDE:

SLIDE 1:
[Composição, fotografia, hierarquia, cor, elementos, ponto focal e superfície de leitura.]

[...]

[Quando imagem gerada ou referência visual fizer parte do fluxo.]

- [foto real]

- [QR]
- [print]
- [documento]

- [...]

[Legenda completa.]

- [...]

- [...]
```

Se uma seção não tiver função real, pode ser omitida.

# PARTE X — COMO ESCREVER CADA SEÇÃO

## 23. Objetivo

Deve descrever a mudança desejada.

Fraco:
> divulgar evento.

Melhor:
> fixar data e proposta do evento antes de apresentar detalhes comerciais.

## 24. Público

Especificar somente quando a segmentação muda:
- mensagem;
- canal;
- linguagem;
- CTA;
- escolha de imagem.

Evitar público genérico sem utilidade.

## 25. Mensagem principal

Deve responder:
> se a pessoa lembrar de uma única ideia, qual deve ser?

## 26. Texto exato da arte

Tudo escrito nessa seção é **copy editorial**, não sugestão.

A designer pode mudar:
- quebra;
- escala;
- alinhamento;
- distribuição.

Não deve:
- reescrever;
- completar;
- inventar.

## 27. Direção visual geral

Deve definir:
- linguagem visual;
- sensação;
- família de fundo;
- cor de acento;
- papel da fotografia;
- grau de densidade;
- continuidade de campanha.

Evitar orientações vazias como:
- “deixar moderno”;
- “usar fotos humanas”;
- “usar identidade ACIRV”.

## 28. Direção por slide

Para cada slide, indicar quando aplicável:
- tipo de composição;
- elemento dominante;
- fotografia;
- hierarquia;
- contraste;
- cor;
- elemento gráfico;
- continuidade.

A direção reduz ambiguidade sem engessar a designer.

## 29. Assets

Se a peça depende de:
- pessoa real;
- parceiro;
- QR;
- logo;
- print;
- número;
- depoimento;
- foto de evento;

o briefing precisa nomear o asset.

Não delegar à designer a tarefa de descobrir qual informação é verdadeira.

## 30. Dados a validar

Marcar explicitamente:
- preço;
- desconto;
- capacidade;
- horário;
- local;
- números;
- estatísticas;
- produto;
- condição comercial;
- autorização;
- depoimento;
- nome/cargo.

Se a informação muda a mensagem central, usar `BLOCKED_DATA_VALIDATION`.

## 31. Legenda

O padrão é:
**LEGENDA FINAL — PRONTA PARA COPIAR**.

A legenda aprofunda; ela não deve servir para esconder uma arte sem mensagem definida.

# PARTE XI — PROMPT PARA GERAÇÃO DE IMAGENS

## 32. Quando usar

Adicionar `PROMPT DE GERAÇÃO VISUAL` quando:
- a IA vai produzir uma referência;
- a IA vai criar background/conceito;
- a imagem não depender exclusivamente de foto documental;
- a direção visual puder ser traduzida em cena/composição.

## 33. Estrutura do prompt

Um bom prompt deve descrever:

1. formato e proporção;
2. contexto ACIRV;
3. família de background;
4. composição;
5. elemento principal;
6. tratamento de imagem;
7. cores/acento;
8. áreas de respiro;
9. sensação desejada;
10. restrições.

### Prompt-base

> Crie uma referência visual conceitual para uma publicação da ACIRV usando ACIRV-MOOD-v1. Preserve azul como âncora, alto contraste, tipografia forte, linguagem humana e contemporânea e acentos de verde, amarelo, laranja ou ciano com função clara. Escolha conscientemente entre cor sólida, degradê monocromático, azul+verde, degradê experimental ou fotografia tratada. Se houver fundo complexo, crie superfície de leitura. Garanta legibilidade em celular e evite microtexto, template corporativo genérico, neon gratuito e excesso de elementos. Adapte ao briefing sem copiar literalmente uma referência.

### Regra importante

Quando o gerador de imagem for usado **sem renderizar texto final confiável**, o prompt deve reservar superfícies de leitura e indicar o local do texto, em vez de depender da IA para acertar toda a tipografia.

# PARTE XII — RESPONSABILIDADES

## 34. Autoria editorial

A copy, o objetivo, a estrutura, a legenda, os dados e a direção visual pertencem ao briefing canônico.

## 35. Designer

A designer pode decidir:
- refinamento de composição;
- quebras;
- escala;
- acabamento;
- posicionamentos dentro da direção;
- soluções técnicas de design.

A designer não deve precisar:
- escrever copy;
- pesquisar dados;
- decidir fatos;
- inventar CTA;
- descobrir qual foto deve ser usada sem orientação.

## 36. Hermes Work

Quando o briefing estiver `PRODUÇÃO_PRONTA`, o Hermes:
- lê o canônico;
- transfere;
- salva;
- verifica;
- registra estado.

O Hermes não:
- reescreve copy;
- troca CTA;
- muda número de slides;
- inventa fatos;
- “melhora” uma direção já fechada.

Quando faltar briefing:
- `BLOCKED_EDITORIAL_BRIEFING`.

Quando faltar dado crítico:
- `BLOCKED_DATA_VALIDATION`.

# PARTE XIII — QUALITY GATE

## 37. Gate editorial

Antes de liberar:

### Conteúdo
- [ ] objetivo claro?
- [ ] público suficiente?
- [ ] mensagem principal definida?
- [ ] texto exato em todos os slides?
- [ ] CTA exato?
- [ ] legenda pronta ou bloqueio explícito?
- [ ] fatos voláteis validados?

### Estrutura
- [ ] formato definido?
- [ ] número exato de slides?
- [ ] função de cada slide clara?
- [ ] capa forte?
- [ ] sequência narrativa coerente?

### Visual
- [ ] azul funciona como âncora?
- [ ] background pertence a uma família intencional?
- [ ] cor de acento tem função?
- [ ] hierarquia tipográfica é clara?
- [ ] não há microtexto?
- [ ] contraste é suficiente?
- [ ] foto detalhada tem superfície de leitura?
- [ ] a peça varia sem perder identidade?
- [ ] não parece template genérico?
- [ ] estética reforça a mensagem?

### Assets e risco
- [ ] assets críticos identificados?
- [ ] autorização de imagem considerada?
- [ ] logo/parceiro correto?
- [ ] preço/desconto/local/horário confirmados?
- [ ] nenhuma promessa foi inferida?

### Executabilidade
- [ ] um terceiro consegue produzir sem adivinhar?
- [ ] o Hermes consegue transferir sem reinterpretar?
- [ ] a designer consegue executar sem escrever conteúdo?

# PARTE XIV — ANTIPADRÕES

## 38. Não fazer

Não criar briefings que:
- tragam só tema, sem copy;
- digam apenas “usar identidade ACIRV”;
- mandem a designer pesquisar;
- usem microtexto;
- concentrem texto demais na arte;
- usem todas as cores com mesma intensidade;
- repitam sempre o mesmo template;
- copiem literalmente referência;
- priorizem estética sobre clareza;
- usem banco genérico quando há imagem real;
- transformem gradiente/neon em ruído;
- coloquem texto pequeno sobre fundo detalhado;
- inventem preço, horário, lote, desconto, cargo ou promessa;
- usem pessoa gerada para representar uma pessoa real;
- deixem para a legenda resolver uma arte editorialmente indefinida.

# PARTE XV — CONSISTÊNCIA E VARIAÇÃO

## 39. Deve permanecer consistente

- reconhecimento ACIRV;
- azul como âncora;
- alto contraste;
- tipografia forte;
- mensagem curta;
- pessoas/histórias reais;
- logo com respiro;
- conexão, movimento e rede;
- qualidade institucional;
- leitura mobile.

## 40. Pode variar

- fundo;
- cor de acento;
- posição do logo;
- alinhamento;
- foto cheia/recorte/colagem;
- densidade;
- linguagem da campanha;
- intensidade e direção de gradiente.

A variedade é parte do sistema.

# PARTE XVI — GOVERNANÇA E SINCRONIZAÇÃO

## 41. Relação com o Design System

Este manual contém **tudo que é necessário para escrever e orientar um briefing visual**, mas não substitui o Design System em assuntos mais amplos como:
- interfaces completas;
- componentes digitais;
- web;
- padrões de produto;
- novas decisões permanentes de marca.

Se uma regra de briefing começar a se repetir e implicar mudança estrutural da identidade, atualizar primeiro [[Design-System-ACIRV]] e depois este manual.

## 42. Relação com ACIRV-MOOD-v1

O `MOODBOARD.md` do Hermes é projeção operacional.

Ele pode:
- ser mais curto;
- ser orientado a geração;
- conter prompt-base;
- manter pesos das referências.

Ele não pode:
- contradizer este manual;
- contradizer o Design System;
- criar regra permanente sem promoção canônica.

## 43. Relação com o Trello

O Trello recebe a versão executável do briefing.

A fonte editorial deve permanecer no GitHub canônico/planejamento.

Atualizações não devem criar novo card quando o card correto já existir; preservar histórico, ID e anexos.

## 44. Regra de evolução

A arquitetura desejada é:

**Design System → Manual Canônico de Briefing + Direção Visual → Planejamento/Briefing específico → Hermes/Trello → Produção → Aprendizado → atualização canônica quando necessário.**

Isso reduz a necessidade de reconstruir a identidade a cada novo briefing e impede que o fluxo operacional crie uma identidade paralela.
